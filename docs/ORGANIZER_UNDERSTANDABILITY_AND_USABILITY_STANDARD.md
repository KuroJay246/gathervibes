# Organizer Understandability and Usability Standard

## Standard

Every organizer-facing page must explain its purpose in plain language, show the selected Working Event, and state the most important boundary that prevents accidental misuse.

## Required Page Pattern

- Page title: name the organizer job, not the implementation area.
- Purpose line: explain why the organizer opens the page.
- Boundary line: explain what the page does not change automatically.
- Primary action: make the most common safe action easiest to find.
- Empty state: explain the next useful action.
- Error state: explain whether the issue is account access, event selection, validation, connectivity, or system failure.

## Usability Rules

- Keep explanations compact.
- Do not repeat long Working Event descriptions inside each page.
- Do not use phase numbers, implementation history, or roadmap language in normal organizer workflows.
- Do not imply a relationship creates an automatic side effect.
- Do not hide Tickets or Check-In behind lower-priority mobile navigation.
- Keep System QA separate from daily event work.
